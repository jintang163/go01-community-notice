# 社区通知公告系统（go01-community-notice）

一个使用 **纯 Go 标准库** 从 0 到 1 构建的社区通知公告系统。物业管理员（admin）发布通知公告，居民（resident）查看通知并维护“已读 / 未读”状态。系统内置前端页面与文件级数据持久化，可通过 Docker 独立运行。

---

## 一、项目简介

在社区（小区 / 物业）场景中，物业需要向居民统一发布通知公告（停水停电、电梯检修、节假日活动、安全提示等），并需要知道“某条通知有多少人已读 / 未读”“某位居民还有多少未读通知”。本系统正是为解决这一需求而设计：

- **管理员（admin）**：登录后台，起草、编辑、发布、置顶、删除通知公告，查看每条通知的阅读统计。
- **居民（resident）**：登录后查看面向自己的通知列表，一眼看到“未读”红点，点开即标记已读；可主动标记已读；可查看历史已读通知。
- **核心业务规则**：通知一旦被管理员更新，所有已读过的居民自动回到“未读”状态，保证居民能看到最新内容——即“**更新即未读**”。

系统使用 Go 1.22 + 标准库（`net/http`、`encoding/json`、`embed`、`sync` 等），**零第三方依赖**，可完全离线构建与运行，适合在受限网络环境下交付。

## 二、功能特性

### 2.1 用户与权限

| 角色 | 能力 |
|------|------|
| 管理员（admin） | 创建/编辑/删除通知，发布/下架通知，置顶/取消置顶，设置优先级与分类，创建居民账号，查看阅读统计 |
| 居民（resident） | 查看已发布通知列表，查看通知详情，主动标记已读，查看个人未读数量，查看历史已读列表 |
| 未登录访客 | 仅可访问登录页，不可查看任何通知内容 |

- 账号体系：管理员通过种子数据初始化（默认 `admin / admin123`，首次启动可改密），管理员可创建居民账号。
- 会话：登录成功后颁发内存 Token（Bearer），带过期时间；登出即失效。
- 口令安全：盐值（salt）+ 多轮迭代 SHA-256 口令哈希（演示级实现，生产建议替换为 bcrypt/argon2）。

### 2.2 通知公告生命周期

通知有三种状态流转：

```
        创建                 发布                 更新（仍为已发布）
[ 草稿 draft ] ───────► [ 已发布 published ] ─────────► [ 已发布 published（UpdatedAt 前移）]
        │                       │
        │  删除 ◄───────────────┘  下架（回退为草稿）
        ▼
     已删除（级联清理阅读记录）
```

- **草稿（draft）**：仅管理员可见，居民不可见（访问返回 404）。
- **已发布（published）**：居民可见；发布时记录发布时间 `PublishAt`。
- **更新**：管理员修改标题 / 正文 / 优先级 / 分类 / 置顶等任意字段后，`UpdatedAt` 前移到当前时间。
- **删除**：物理删除通知，并级联清理该通知的所有阅读记录。
- **置顶（pinned）**：置顶通知在居民列表中始终排在最前。
- **优先级（priority）**：整数，数值越大越靠前；用于同级置顶之后的二次排序。
- **分类（category）**：如“物业通知 / 安全提示 / 活动公告 / 设施维护”等，支持按分类筛选。

### 2.3 已读 / 未读语义（核心）

> **定义**：一条通知对某居民“已读”，当且仅当存在一条阅读记录，且该记录的 `ReadAt ≥ 通知.UpdatedAt`。

由此派生出系统的核心规则：

1. **查看详情即标记已读（幂等）**：居民点开通知详情，系统以“当前时间”更新阅读记录的 `ReadAt`。
2. **更新即未读**：管理员更新已发布通知后，`UpdatedAt` 前移，导致历史阅读记录的 `ReadAt < 新 UpdatedAt`，居民重新变为“未读”，下次进入列表会再次看到未读红点。
3. **主动标记已读**：居民可在列表中对某条通知主动“标记已读”，效果与点开详情一致。
4. **草稿不可读**：草稿对居民不可见，无已读 / 未读概念。
5. **删除级联**：通知被删除后，其阅读记录一并清理；居民账号被删除后，其阅读记录一并清理。

### 2.4 列表排序规则

居民通知列表按如下优先级排序：

1. **置顶（pinned=true）优先**；
2. 其次按 **优先级（priority）降序**；
3. 最后按 **发布时间（PublishAt）倒序**（最新发布的在前）。

管理员后台列表默认按创建时间倒序，并可按状态 / 分类 / 关键词筛选。

### 2.5 统计

- **管理员全局统计**：通知总数、草稿数、已发布数、置顶数、居民总数、今日新增阅读数等。
- **单条通知统计**：该通知的总阅读数、已读居民数、未读居民数、已读率。
- **居民个人统计**：未读通知数量、已读通知数量、总数。

### 2.6 数据持久化

- 系统采用 **文件级 JSON 持久化**：所有用户、通知、阅读记录保存在单一数据文件（默认 `data/store.json`）中。
- 写操作（创建 / 更新 / 删除）原子落盘（先写临时文件再 `os.Rename` 重命名，避免写入中途崩溃导致数据损坏）。
- 服务重启后自动加载该文件恢复全部状态。
- Docker 部署时通过 volume 挂载 `./data` 目录实现跨容器生命周期的持久化。

### 2.7 前端页面

内置轻量前端（HTML + 原生 CSS + 原生 JavaScript，无构建工具，无前端框架），通过 Go `embed` 打包进二进制：

- `/login` 登录页
- `/admin` 管理员后台（通知管理 + 用户管理 + 统计看板）
- `/resident` 居民首页（通知列表 + 未读红点 + 标记已读）
- `/notices/{id}` 通知详情页（居民访问自动标记已读）
- `/static/*` 静态资源（样式、脚本）

## 三、业务逻辑详述

### 3.1 状态机与可见性

| 操作 | 管理员 | 居民 | 未登录 |
|------|--------|------|--------|
| 查看草稿 | ✅ | ❌ 404 | ❌ 401 |
| 查看已发布 | ✅ | ✅ | ❌ 401 |
| 创建通知 | ✅ | ❌ 403 | ❌ 401 |
| 更新通知 | ✅ | ❌ 403 | ❌ 401 |
| 删除通知 | ✅ | ❌ 403 | ❌ 401 |
| 发布 / 下架 | ✅ | ❌ 403 | ❌ 401 |
| 置顶 / 取消置顶 | ✅ | ❌ 403 | ❌ 401 |
| 标记已读 | — | ✅ | ❌ 401 |
| 查看阅读统计 | ✅ | ❌ 403 | ❌ 401 |

### 3.2 “更新即未读”实现原理

不使用“已读”布尔标志位，而使用 **时间戳比较** 推导已读状态：

```
isRead(user, notice) =
    存在阅读记录 rr(user, notice)  且  rr.ReadAt >= notice.UpdatedAt
```

- 管理员每次更新通知，将 `notice.UpdatedAt` 设为当前时间。
- 由于 `rr.ReadAt`（居民上次阅读时间）小于新的 `UpdatedAt`，`isRead` 变为 `false`。
- 居民下次打开列表，看到“未读”，再次点开详情，`ReadAt` 被更新为当前时间（≥ `UpdatedAt`），重新变为已读。

该设计避免了“更新通知时遍历所有居民清零已读标志”的额外开销，仅需一次时间戳比较。

### 3.3 输入校验

- 用户名：3–32 字符，字母数字下划线。
- 口令：6–64 字符。
- 通知标题：1–200 字符；正文：1–20000 字符。
- 优先级：0–999 整数。
- 分类：可选，最长 32 字符。
- 所有写接口对必填字段、长度、类型进行校验，失败返回 `400` 与明确错误信息。

### 3.4 并发安全

- 存储层使用 `sync.RWMutex` 保护内存数据结构，读操作并发、写操作独占。
- 持久化在写锁释放后触发（快照落盘），避免锁重入死锁。
- 会话管理器内部使用独立的 `sync.RWMutex`。
- HTTP 服务由标准库自动并发处理请求，业务逻辑无共享可变状态泄漏。

### 3.5 优雅关闭

服务收到 `SIGINT` / `SIGTERM` 时：
1. 停止接收新连接；
2. 等待进行中的请求完成（带超时）；
3. 最后一次落盘持久化数据；
4. 退出。

## 五、数据模型

### 5.1 实体

**User（用户）**

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | string | 主键，自动生成 |
| Username | string | 登录名，唯一 |
| PasswordHash | string | 口令哈希（盐+迭代 SHA-256，base64） |
| PasswordSalt | string | 盐值（base64） |
| Iterations | int | 迭代次数 |
| Role | string | `admin` / `resident` |
| DisplayName | string | 显示名 |
| CreatedAt | time.Time | 创建时间 |
| UpdatedAt | time.Time | 更新时间 |

**Notice（通知公告）**

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | string | 主键 |
| Title | string | 标题 |
| Content | string | 正文 |
| Status | string | `draft` / `published` |
| Priority | int | 优先级（大者优先） |
| Pinned | bool | 是否置顶 |
| Category | string | 分类 |
| AuthorID | string | 创建者 ID |
| PublishAt | *time.Time | 发布时间（草稿为 nil） |
| CreatedAt | time.Time | 创建时间 |
| UpdatedAt | time.Time | 更新时间（已读判定的基准） |

**ReadRecord（阅读记录）**

| 字段 | 类型 | 说明 |
|------|------|------|
| ID | string | 主键 |
| UserID | string | 居民 ID |
| NoticeID | string | 通知 ID |
| ReadAt | time.Time | 最近一次阅读时间 |
| CreatedAt | time.Time | 记录创建时间 |

### 5.2 关系

- 一个 User（admin）创建多个 Notice。
- 一个 User（resident）对多个 Notice 各有一条 ReadRecord。
- 删除 Notice → 级联删除其全部 ReadRecord。
- 删除 User → 级联删除其全部 ReadRecord。

## 六、API 参考

所有 `/api/**` 接口返回 JSON，错误格式：`{"code":"...","message":"..."}`。需鉴权接口要求请求头 `Authorization: Bearer <token>`。

### 6.1 鉴权

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| POST | `/api/auth/login` | 公开 | 登录，返回 token 与用户信息 |
| POST | `/api/auth/logout` | 已登录 | 登出，失效当前 token |
| GET  | `/api/auth/me` | 已登录 | 获取当前登录用户 |
| POST | `/api/users` | admin | 创建居民账号 |
| GET  | `/api/users` | admin | 用户列表 |
| DELETE | `/api/users/{id}` | admin | 删除用户（级联清理阅读记录） |

### 6.2 通知

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET | `/api/notices` | 已登录 | 列表（居民仅已发布；admin 可加 `status/category/q` 筛选） |
| GET | `/api/notices/{id}` | 已登录 | 详情（居民访问草稿返回 404，访问后标记已读） |
| POST | `/api/notices` | admin | 创建通知（默认草稿） |
| PUT | `/api/notices/{id}` | admin | 更新通知（前移 UpdatedAt） |
| DELETE | `/api/notices/{id}` | admin | 删除通知（级联清理阅读记录） |
| POST | `/api/notices/{id}/publish` | admin | 发布 |
| POST | `/api/notices/{id}/unpublish` | admin | 下架回退为草稿 |
| POST | `/api/notices/{id}/pin` | admin | 切换置顶 |

### 6.3 已读 / 未读

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET | `/api/notices/{id}/read-status` | resident | 查询该通知对当前用户的已读状态 |
| POST | `/api/notices/{id}/read` | resident | 主动标记已读（幂等） |
| GET | `/api/me/notices` | resident | 我的通知列表（含已读 / 未读标识） |
| GET | `/api/me/unread-count` | resident | 我的未读数量 |

### 6.4 统计

| 方法 | 路径 | 角色 | 说明 |
|------|------|------|------|
| GET | `/api/stats` | admin | 全局统计看板 |
| GET | `/api/stats/notices/{id}` | admin | 单条通知阅读统计 |

### 6.5 页面

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/` | 重定向到 `/login` 或对应角色首页 |
| GET | `/login` | 登录页 |
| GET | `/admin` | 管理员后台 |
| GET | `/resident` | 居民首页 |
| GET | `/notices/{id}` | 通知详情页 |
| GET | `/static/*` | 静态资源 |
| GET | `/healthz` | 健康检查 |

## 八、安全说明

- 口令哈希采用盐值 + 多轮迭代 SHA-256（演示级，对抗彩虹表；生产环境建议替换为 bcrypt / argon2）。
- 会话 Token 使用 `crypto/rand` 生成的高熵随机串。
- 不存储明文口令；登录时仅比对哈希。
- 前端 Token 存放于 `localStorage`，请求时通过 `Authorization` 头携带（注意 XSS 防护）。
- 本系统为社区内部演示用途，未实现完整 HTTPS / CSRF / 限流，生产部署请置于反向代理之后并补充相应防护。
